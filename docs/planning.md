# 차곡차곡 기획 요약

> 공모전 접수양식(기획서)의 핵심 내용을 정리한 문서입니다.

## 문제
- 차 한 대를 여러 사람이 나눠 쓰는 가정에서 "차 어디에 댔어?"가 반복됩니다.
- GPS 기반 위치 서비스는 수십~수백 m 오차가 있고, 지하주차장의 층·구역을 구분하지 못합니다.
- 휴대폰 메모는 사용자가 직접 기억해 앱을 열어야 해서, 바쁜 하차 순간에 대부분 놓칩니다.
- 연료 부족, 차량 이상 같은 인수인계 정보가 말로만 오가다 누락됩니다.

## 해결
**사용자가 기억할 필요 없이, 차가 정차 순간을 감지해 먼저 묻습니다.**
운전자의 한마디를 받아 적어 다음 운전자와 가족에게 건네는 '인수인계의 바통'이 됩니다.

## 기능 우선순위
| 우선순위 | 기능 | 목표 시점 |
|---|---|---|
| ① 핵심 | 주차 음성 메모 (자주 가는 주차장 기억, 원본 음성 보존 포함) | 1단계 프로토타입 → 2단계 완성 |
| ② 기반 | 가족 연결 (QR, 웹앱) · 다음 운전자 브리핑 | 2단계 |
| ③ 보조 | 음성 장소 핀 → 내비 길 안내 | 2단계 |
| 확장 | 전기차 충전 바통터치, 퀴즈 드라이브, 차량 관리 알림, B2B | 기획서에만 기재 |

## 주차 감지 로직
1. Vehicle SDK 시동·기어 상태 (지원 여부 확인 필요)
2. 속도 0이 일정 시간 지속 → 음성으로 확인
3. 화면의 '주차 완료' 버튼

## 시연 시나리오 (2차 PT)
차 화면(에뮬레이터)에서 "B구역 기둥 14"라고 말하면, 심사위원 앞 휴대폰 웹앱에 주차 카드가 즉시 나타나고 원본 음성이 재생됩니다.

## 확인이 필요한 사항
- [ ] Vehicle SDK에서 시동·기어 상태를 지원하는지 (에뮬레이터에서 확인)
- [ ] Pleos 환경에서 Firebase 푸시 알림이 동작하는지
- [ ] 예상 MAU 산식에 쓸 실제 통계 (Pleos Connect 탑재 차량 수 등)
